SANADBusiness model
Investor and validation view

Assess one workflow. Install only if local wins.

SANAD assesses one business workflow, installs a local system only when the test supports it, hands over an environment the customer owns, and offers optional care after handover. Pursue a job only when the workflow has a clear local advantage; otherwise recommend cloud.

What is sold

Buyers pay for a tested workflow, retrieval and access rules that work on their material, a documented handover they own, and optional maintenance. They are not paying for a runtime they could install themselves.

How money comes in

Revenue comes from paid assessment, implementation, later expansion work and optional care. Care must stay bounded. If support turns into unlimited tickets and answer-quality disputes, the recurring model stops working.

Why the customer still owns it

The ownership claim only works if SANAD avoids unnecessary lock-in.

Customer data stays separate

Business documents and backups should not be trapped inside one interface or runtime.

Components can be replaced

Ollama, llama.cpp, MLX or another runtime can be changed if licensing, pricing or support changes.

Support is optional

Stopping the care plan should not disable the system. SANAD is paid to maintain it, not to unlock it.

What would falsify the idea

  • Cloud is often good enough.If most qualified customers are better served by existing cloud products, the addressable market is too small.
  • The DIY setup is cheap.A local runtime and browser interface are no longer scarce. SANAD has to earn its fee through testing, retrieval design, access and backup rules, update policy, handover and the option to decline the install.
  • Local models may not match the quality customers expect.Each use case needs testing before hardware is sold or installed.
  • Support can become labour-heavy.The business needs standard builds and clear support boundaries or monthly care fees will be eaten by service time.
  • Security expectations can exceed a small provider's capability.Higher-risk work may require specialist partners, formal controls or a narrower scope.
Prototype business model. Pricing, demand and support effort still need validation through real customer discovery and pilots.

The first workflow

The first build is deliberately narrow. It focuses on document search and drafting because those tasks are easy to test against agreed source material.

Search selected documents

Staff ask questions across an approved document set and receive answers with source references.

Draft from the same material

Staff can prepare first drafts or summaries using retrieved source material, with a person checking the result before use.

Run a quality test first

SANAD tests the workflow on sample questions before recommending hardware or installation.

Keep later features out of the first build

Transcription, voice and a general high-frequency assistant only proceed if the hardware and business task justify them.

What the assessment tests

The assessment produces a go or no-go recommendation. The buyer pays for the test and the recommendation, not for a pre-decided hardware sale.

Qualification rule

Local work only proceeds when all four conditions are met.

  • One workflow.The customer can name the first task clearly enough to test it.
  • A reason local wins.There is a specific control, continuity or operating reason to prefer local over a standard cloud product.
  • No internal owner for the stack.The customer needs SANAD to select, configure and maintain the supported setup.
  • The quality test passes.The local system meets the agreed threshold on the customer’s material. If any condition fails, the assessment ends with a cloud recommendation or a no-go.

Care boundary

A care plan only works if the support boundary is clear before a monthly price is set.

Included

  • Patches on the supported stack
  • Model updates from an approved list
  • Scheduled document reindex
  • Restore test
  • User add and remove

Not included

  • New workflows
  • New data sources
  • Unlimited answer-quality debates
  • Custom security reviews
  • Air-gapped deployments
